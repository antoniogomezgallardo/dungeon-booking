# Documentation index

Documentation follows [Diátaxis](https://diataxis.fr/): tutorials, how-to guides, reference and
explanation are kept in separate documents so each one does one job well.

| Folder                          | Type                    | What you find there                                                         |
| ------------------------------- | ----------------------- | --------------------------------------------------------------------------- |
| [product/](product/)            | explanation             | Product vision and roadmap (owned by the PM)                                |
| [adr/](adr/)                    | reference               | Architecture Decision Records: why things are the way they are              |
| [architecture/](architecture/)  | explanation             | How the system works end to end                                             |
| [testing/](testing/)            | explanation + reference | Test strategy, per-story test plans, templates                              |
| [runbooks/](runbooks/)          | how-to                  | Run locally, release, debug, roll back                                      |
| [releases/](releases/)          | reference               | Release notes per version                                                   |
| [learning/](learning/README.md) | tutorial + explanation  | The pedagogical layer: curriculum, sprint journals, concept cards, glossary |
| [postmortems/](postmortems/)    | explanation             | One write-up per complex failure investigated                               |

Rules we keep: verify before writing, one file one purpose, link both ways, date what expires,
copy-pastable commands without a `$` prompt.
